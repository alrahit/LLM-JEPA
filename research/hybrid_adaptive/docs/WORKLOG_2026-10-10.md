## Key findings (code + traces)
1. InfoNCE in finetune_hybrid.py builds a B x B similarity matrix with B = per-device batch size = 1 in all runs.
   => jepa_loss == 0 exactly and retrieval accuracy == 1, so S == 0 (see qwen/traces/*.json: every entry has jepa_loss=0, S=0).
   => lambda follows lambda *= exp(eta*(S_bar - tau)) = exp(-0.025) = 0.9753 per micro-step after 20 warmup calls; below 1e-6 after about 35 optimizer steps.
   => the "LinAlign" runs received no JEPA gradient (effectively LM-only).
2. The "SFT" runs were launched without --regular/--infonce/--linalign, so they used the default cosine JEPA with lbd=0.1 (active at batch 1).
   => they are "static cosine-JEPA (lambda=0.1)", not plain SFT.
3. All three views are padded to max_length=512, but mean length is 50 tokens (SYNTH) / 75 (SPIDER): most compute is padding.
4. Logged trainer loss is about 16x the per-micro-batch lm_loss (suspected missing gradient-accumulation division; unverified).
